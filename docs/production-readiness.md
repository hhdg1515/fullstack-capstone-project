## Atlas access and recovery decisions

Configuration findings above are separate from recommendations. The current DB-scoped `readWrite` role is a useful boundary; it is not a production credential and no production DB is assumed. App startup verifies indexes rather than creating them. Any finer custom role, separate backup/admin user, credential rotation or tier change requires owner approval and a verified target.

Do not infer a stable IP from one function invocation or one runner. Low-cost options are a short, explicitly approved staging test window with reviewed expiration, or an already available owner-operated fixed-egress host/runner. Neither solves Vercel's own dynamic egress automatically. Provider static egress/private endpoints may require paid plans/tiers and are proposals only. A durable launch policy must cover both API runtime and verification/backup clients while keeping production separate.

For recovery, prefer an owner-controlled encrypted volume and DB-scoped `mongodump` archive, checksum and manifest; never publish private DB backups as unencrypted Actions artifacts or in the repository. Use Database Tools' private config-file support to avoid credentials in argv/history. Atlas managed backups are unavailable on Free M0. Logical exports are not point-in-time backups: arrange a no-writes window and verify cross-collection consistency. Restore only into an explicitly approved empty isolated target, with namespace remapping and no automatic `--drop`, then verify data/ownership/indexes and revoke restored sessions before any eventual service cutover. The [operations runbook](operations-runbook.md) contains the proposed low-cost procedure, access options and provider references. No export, restore or backup configuration is executed by this audit.

## Implemented low-risk changes and compatibility

- Hosted startup/readiness now reports allowlisted phase/category with server-generated request IDs; duplicate failure events are throttled per warm instance. Driver error messages and private request fields stay out of responses/logs. MongoDB connection selection/connect/pool waits are bounded independently; pool size and native recovery remain unchanged.
- Hosted `GET /api/live` answers without a database for liveness. The existing `/api/health` JSON shape/readiness checks and every supplied deployment fingerprint fence remain intact. No new migration/index requirement is introduced.
- Legacy gift search now escapes regex syntax, rejects structured/repeated/unknown/oversized filters and malformed whole-number ages, and caps query execution at five seconds. Ordinary case-insensitive search, response arrays, fixture IDs and all 16 bundled records are preserved. Clients that intentionally sent raw regex or malformed filters must use literal supported fields; this is the intentional compatibility tightening.
- Frontend requests abort after 15 seconds including response-body reading; no write is retried automatically and no timeout is treated as a logout. An interrupted write can already have committed, so users are told to refresh before retrying.
- React Router is patched from 6.20.1 to compatible 6.30.6, without a major migration. Automated axe checks exposed low contrast on footer links and secondary outline controls; those colors are darkened on the existing surfaces. Layout/navigation/product scope are unchanged.
- New automated accessibility checks use owned disposable local data, never remote fixtures. Existing desktop/mobile two-user workflows, HTTPS assertions, bypass handling, owner/SHA/fingerprint gates, synthetic budgets and bounded cleanup are retained.

## Dependency assessment

`npm audit --omit=dev --json` for backend production dependencies exits 0 with **0 findings**. The final frontend full-tree audit exits 1 with **99 findings: 14 low, 46 moderate, 35 high, 4 critical**. CRA lists build/test tools in its production dependency tree, so `--omit=dev` alone cannot identify shipped browser vulnerabilities. The earlier audit snapshot reported 387; audit metadata is time/service-sensitive and the count difference is not evidence that a three-package router patch fixes every removed report.

The compatible router patch removes the previously reported high-severity router/open-redirect paths and updates `@remix-run/router`. Two moderate `react-router` advisories remain, propagated to `react-router-dom`: [backslash redirects](https://github.com/advisories/GHSA-wrjc-x8rr-h8h6) and [SSR error hydration](https://github.com/advisories/GHSA-337j-9hxr-rhxg). The application uses client-only BrowserRouter, validated post-login internal destinations and fixed/prefixed internal links; it does not use SSR hydration. That narrows exposure but does not erase the audit findings. The reported fix requires a router major upgrade and is deferred for a focused compatibility review. Build/toolchain risks, including critical transitive reports, require owner disposition before launch; no force upgrade or stack replacement is performed.
